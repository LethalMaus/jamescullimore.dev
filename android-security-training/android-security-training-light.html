Why this matters

Android security issues often hide outside normal app logic.

Android security risks often live outside the feature code: TLS trust, app signing, deep links, local storage, WebView settings and exported components. This training teaches developers how those risks appear in real Android projects and how to verify the fix.

Syllabus

Four focused Android security modules

Each module pairs the underlying Android mechanics with practical testing, secure implementation and verification.

Module 01

Network Trust & Payload Encryption

Understand Android HTTPS trust decisions and how to defend sensitive client-server traffic.

  • HTTPS
  • Certificate pinning
  • NetworkSecurityConfig
  • Certificate Transparency
  • E2E payload concepts
Module 02

Reverse Engineering & APK Tampering

Inspect shipped APKs, identify exposed implementation details and understand tamper controls.

  • JADX
  • apktool
  • Hardcoded secrets
  • R8 and ProGuard
  • Signing checks
Module 03

Deep Links, Intents & Local Storage

Review Android entry points, URI validation and storage choices for sensitive app data.

  • App Links
  • URI validation
  • EncryptedSharedPreferences
  • DataStore
  • Room and SQLCipher
Module 04

WebView & Exposed Components

Audit WebView settings and Android components that can expand an app's attack surface.

  • JavaScript interfaces
  • Unsafe URL loading
  • Exported components
  • Provider leakage
  • Shared UID risks

Hands-on labs

Learn by attacking, fixing and retesting

Participants work with a dedicated Android demo app containing vulnerable and hardened examples. The labs keep the loop concrete: inspect the behavior, exploit the weakness, harden the app and retest the same path.

  • adb
  • logcat
  • mitmproxy
  • JADX
  • apktool
  • Android Studio
  • vulnerable and secure build variants
