Editable Config Files: A UI-less Way to Configure Android Apps and Services

By James Cullimore • Feb 4, 2025 • 9 min read

Configuration files can play a crucial role in many Android applications, allowing users to customize settings without modifying the app’s source code. Whether adjusting UI preferences, toggling experimental features, or managing backend endpoints, a well-designed config file can offer flexibility while keeping the app dynamic. However, one challenge developers often face is ensuring that changes to these files take effect while the app or service is running, without requiring a restart.

In this article, we’ll explore how to create a configuration file that users can edit in real time while an Android app or service is running. We’ll start by discussing common use cases where such an approach is beneficial, from debugging and feature toggling to adjusting app behavior based on user preferences. Next, we’ll walk through the setup process, detailing how to structure the config file and where to store it for easy access.

Beyond just setting up the file, we’ll dive into how to observe changes in real time, using FileObserver to detect modifications and apply them dynamically. Finally, we’ll cover error handling strategies to prevent crashes or unintended behavior when the config file is edited incorrectly as well as a caveat to it all. By the end of this guide, you’ll have a clear roadmap for integrating a robust and user-friendly config system into your Android application.

Use Cases

A dynamically editable config file can be a powerful tool in various Android app development scenarios. It provides a way to modify settings, toggle features, or fine-tune an application’s behavior without rebuilding or restarting the app. This approach is especially useful in cases where a full-fledged UI for configurations is impractical or unnecessary.

Avoiding the Need for a UI

Building a user interface for every possible configuration setting can be time-consuming and may not always be justified, especially if the settings are meant for advanced users, testers, or developers. Instead of investing time in creating menus, dialogs, and preference screens, a simple text-based config file allows users to modify parameters directly. This is particularly helpful in applications where the number of configuration options is large or frequently changing.

Managing Background Services Without a UI

Many Android applications include background services that operate without a traditional user interface. For example, a media streaming service, a network monitor, or an automation tool may run continuously in the background. In such cases, an editable config file allows users to update settings — such as logging levels, server endpoints, or operational parameters — without needing an app UI or restarting the service.

Enabling Dynamic Debugging and Testing

During development and testing, developers often need to adjust settings like API keys, feature flags, or performance parameters. Instead of recompiling the app for each change, an external config file provides a way to tweak values on the fly. This is particularly useful for debugging, where you may want to enable verbose logging or switch between test and production servers without modifying source code.

Customization for Power Users

For certain applications, advanced users may appreciate the ability to customize behavior beyond what’s available in standard settings. Power users of automation apps, media players, or system utilities may want to fine-tune performance, override default behaviors, or add experimental features. A config file offers a low-barrier way for them to modify these settings while the app is running.

Remote Configuration for IoT and Enterprise Apps

In enterprise or IoT applications, administrators may need to push configuration updates remotely to multiple devices without user intervention. By using a config file stored in an accessible location, such as internal storage or an external server, the app can dynamically load new settings without requiring manual updates or app restarts.

Why These Settings Matter

isLenient = true

  • Allows the parser to handle minor formatting inconsistencies (such as unquoted JSON keys or trailing commas).
  • Helps when users manually edit the file and introduce small errors.

encodeDefaults = true

  • Ensures that when a new config file is created, all default values are explicitly written.
  • This makes it easier for users to understand available options without referring to external documentation.

ignoreUnknownKeys = true

  • Prevents crashes if the config file contains extra fields that are not defined in the app’s data model.
  • Useful when upgrading the app — older config files won’t break even if new settings are introduced.

explicitNulls = false

  • Avoids writing null values to the file, keeping it cleaner and more readable.
  • When loading the config, missing values will fall back to their default values in the data class.

Caveat: Editing the Config File

While providing users with a dynamic, editable configuration file can be incredibly useful, it’s important to consider that most users may not be familiar with directly editing raw files, especially when the config file is in an uncommon or structured format like JSON. To ensure a smooth experience for users, there are some key points to keep in mind:

Specialized Editing Tools Required

  • Editing a configuration file directly may require the user to have an appropriate app for handling JSON files or the specific format you’ve chosen. Android’s built-in file explorer won’t offer a user-friendly way to modify JSON unless the user has a compatible text editor or JSON viewer installed.
  • If the config file is in a non-standard format, it’s essential to guide users on how to edit the file or suggest tools that can simplify the process. Consider providing links to recommended apps for this purpose.

Risk of Incorrect Modifications

  • Manual editing introduces the possibility of errors, such as incorrect JSON formatting, missing fields, or invalid data types. While we’ve made efforts to handle such errors gracefully through the app (e.g., using ignoreUnknownKeys = true), improperly edited files can still cause issues, especially if users inadvertently break the structure.
  • It’s important to provide clear documentation or in-app guidance to help users understand what they can modify, how to properly format the file, and how to avoid common mistakes.

Providing a Better Editing Experience

  • To minimize issues, consider integrating a simple UI in the app that can generate or modify configuration data in a structured way. This approach eliminates the need for users to manually edit the file while still offering flexibility and customization.
  • For more advanced users, you might want to include a built-in editor that validates the data format or auto-corrects errors to some extent.

While editing the config file directly provides flexibility, it’s essential to weigh the trade-off between giving users full control and the risk of errors. Offering guidance or better editing tools can help ensure that the experience remains smooth for both technical and non-technical users alike.

Conclusion

In this article, we explored how to create a user-editable configuration file for an Android app or service, allowing dynamic updates without requiring a restart. This approach provides flexibility, especially when a UI for managing configurations isn’t available or practical.

Use Cases for a Config File

  • Useful for persistent configurations that remain across app updates or reinstalls.

Setting Up File Access Permissions

  • We request permission from the user to select a directory for storing the config file.
  • Permissions are persisted using takePersistableUriPermission() to retain access after app restarts.

Ensuring a Default Config File Exists

  • The app checks if the config file is missing or corrupted and regenerates it with default parameters.
  • The file provides a structured template to help users understand what they can modify.

Handling JSON Parsing Safely

  • Kotlinx Serialization settings like ignoreUnknownKeys = true and isLenient = true make JSON handling more flexible.
  • This prevents crashes due to missing or extra fields while ensuring clean and readable configuration files.

Observing Changes with FileObserver

  • Instead of requiring a restart, a FileObserver detects when the user modifies the config file.
  • The app reloads the configuration dynamically and applies changes instantly using an interface.

By implementing this system, we allow users to customize the app’s behavior efficiently, making it more adaptable while maintaining stability.
